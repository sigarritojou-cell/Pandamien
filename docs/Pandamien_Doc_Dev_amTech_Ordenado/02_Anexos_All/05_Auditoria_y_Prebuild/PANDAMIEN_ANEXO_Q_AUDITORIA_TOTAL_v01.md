### Oleada 7 — Primera pasada integral posterior a la consolidación v07

---

## 0. Estado del documento

Este documento abre formalmente la **Oleada 7 — Auditoría total** del proyecto.

No sustituye al GDD, al changelog ni al plan.  
Su función es verificar que el corpus actual de PANDAMIEN —ya muy musculado en ciclos, exterioridad, TV, criatura y confrontación final— no se esté sosteniendo en contradicciones, huecos de nomenclatura, inflación de alcance o dependencias mal cosidas.

Esta auditoría se ha planteado como una **auditoría de producción y canon**, no como una reescritura del proyecto desde cero.

---

## 1. Alcance auditado

Esta primera pasada audita, de forma transversal:

- coherencia de canon central,
- coherencia entre oleadas cerradas y activas,
- estado de anexos y relación entre fuente activa y archivo satélite,
- nomenclatura de sistemas y variables,
- integración entre ciclos authored y bloques de Oleada 5 / Oleada 6,
- riesgos de build y de alcance,
- y prioridad real de cierre para MVP y juego completo.

No pretende validar todavía:
- cada línea exacta de cada escena,
- cada asset individual,
- ni cada tabla granular satélite no presente en fuente activa.

Eso quedará para pasadas posteriores o para validación al reinyectar archivo satélite completo.

# 4.A. Canon central

## Dictamen
**VERDE**

## Observación
El núcleo duro del proyecto está bien cerrado y no muestra contradicción gruesa:
- high concept,
- estructura día/noche,
- apartamento como sistema,
- puerta atrancada,
- criatura gestada,
- continuidad relacional,
- lectura literaria,
- TV como personaje,
- exterioridad como contagio interpretativo.

## Fortaleza principal
El proyecto sabe ya qué es y qué no es.

## Riesgo residual
Que futuras piezas authored finas introduzcan soluciones que parezcan “buenas ideas” pero rompan:
- la intimidad del horror,
- la lógica del apartamento,
- o la promesa de la puerta.

## Acción
No reabrir el corazón del canon salvo contradicción grave.  
A partir de aquí, la auditoría debe coser, no reinventar.

# 4.C. Fuente activa vs archivo satélite

## Dictamen
**ÁMBAR CONTROLADO**

## Observación
El sistema documental admite bien que parte del corpus viva fuera de la fuente activa. Eso no es un problema en sí.  
El problema aparecería si:
- el maestro no reflejara lo que existe,
- el changelog no consolidara estados,
- o el plan quedara atrasado respecto a los anexos satélite.

## Fortaleza principal
La regla ya existe y está bien formulada.

## Riesgo real
Que el satélite crezca mucho y el proyecto empiece a depender de memoria informal para:
- saber qué versión es la buena,
- qué anexo manda,
- o qué bloque quedó realmente aprobado.

## Acción
Toda pieza satélite relevante debe quedar reflejada en:
- GDD,
- changelog,
- plan,
- y, desde esta auditoría, **matriz de control de corpus**.

# 4.G. Nomenclatura y variables

## Dictamen
**ÁMBAR**

## Observación
La lógica de variables es fuerte, pero el proyecto ya ha acumulado suficiente volumen como para necesitar una limpieza final de:
- nombres,
- prefijos,
- agrupaciones,
- equivalencias entre documentos,
- y variables maestras vs variables locales.

## Riesgo real
No tanto contradicción conceptual, sino:
- duplicidad semántica,
- variables que significan casi lo mismo,
- o términos que cambian ligeramente entre anexos.

## Ejemplos de zonas delicadas
- presión / deuda / hostilidad / amenaza íntima,
- funciones de criatura vs estados de criatura,
- contacto / irreversibilidad / apertura / contención,
- umbral / exterioridad / entrada / pasillo / borde.

## Acción
Abrir subpaquete:
**Q.4 — Diccionario de variables y nomenclatura unificada**

## Riesgo real
Que el proyecto quede:

**Q.5 — Matriz de cruce transversal por ciclos**
para revisar, ciclo por ciclo:
- qué roba la TV,
- qué aprende la criatura,
- qué presiona el exterior,
- y qué se prepara para el final.
